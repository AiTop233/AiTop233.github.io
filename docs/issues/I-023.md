## 边界

- 只做评估，不做产品化；不进 `src/panup/`，不接 REST
- 不做去台标、去硬字幕、超分——这些要模型与大量算力，不在个人工具的成本结构里
- 不评估「绕过平台审核」的任何手段

## 已知的坑（评估时必须覆盖）

- **必然落地**：网盘不能在线编辑内容，所以任何媒体加工都是「下载 → 处理 → 重传」，双向流量
- **必然破秒传**：内容变了 md5 就变，原来能秒传的文件变成整传，且平台可能重新审核
- **裁片头必然有误判**：固定时长裁会切到正片；黑帧/静音检测遇到「黑场转场」会误切。误切的代价是资源废掉
- **加水印是确定性的**：`overlay` / `concat` 不会误伤内容，但会让文件变大、需要重编码
- **责任**：给他人资源加自己的广告再分发，是二次分发行为，风险自担；建议默认关闭

## 过程记录

- 前置判断（`SOURCES.md` §5）：`name` 类加工零成本、`media` 类约 3 倍时间与流量，两者必须分开排期
