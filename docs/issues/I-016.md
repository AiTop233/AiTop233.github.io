## 目标

- 意图：一条命令就能把文件同时传到几个盘、每个盘各放各的目录，并给这次上传起个标题（目标）；现在 `--pan` 只能给一个、`--dir` 只有一个、标题固定取文件名（现状）；不做则多盘场景要敲多遍命令、标题永远受文件名约束（代价）
- 行为：`--pan "盘名:目录"` 可重复，只写 `盘名` 时用该盘默认目录；`--title` 指定标题，缺省用文件名；缺目录、未知盘、重复盘给出明确报错而不是静默取默认
- 机制：`--pan` 改 `action="append"` + 解析 `盘名:目录`；转成 `targets` 交给 `publish_task`；沿用现有错误信封与退出码

## 过程记录

- `--pan` 改 `action="append"`，值按第一个冒号切成「盘名:目录」；不带目录时先看 `--dir`（保留旧命令兼容），再看该盘在 `config.toml` 的默认目录。
- 盘名合法性、重复盘校验放在 core 的 `_check_targets`（不是 CLI），这样 Web 入口复用同一套校验，不必各写一遍。
- 输出从「一条链接」变「逐盘列出 + 失败项单独报到 stderr」；任一盘失败时退出码为 1（AC-06 失败可见）。

## 自验

- [x] A1 单测：`_parse_targets` 4 例（盘名:目录拆分、`--dir` 兜底、显式目录优先、空值报错）+ 多盘一次上传 / 未知盘 / 重复盘 3 例；全套 100 例绿。变异检查：`if not remote:` 改 `if False:` → 2 例变红 → 还原绿。
- [x] A2 真实：`--pan "baidu:/panup验收-多盘" --pan "quark:/panup验收-多盘" --title "I016多盘自验" --doc feishu` → 两盘各自出链接，文档最顶出现一节「261109 I016多盘自验」+ 百度行 + 夸克行（index 1）。
- [x] A3：机制侧由 `test_partial_failure_writes_only_success` 覆盖（夸克 share 抛错时只写百度一行）；真实部分失败留人验收。
- [x] A4 真实：同命令重跑 → 两盘均「去重命中，未重新上传」，文档不再插新节（块数 142 不变）。
- 附带修复（同属 I-015 语义）：去重命中的盘不再触发写文档，否则重跑会插重复节。
