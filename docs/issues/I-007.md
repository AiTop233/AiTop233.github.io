## 目标

- 意图：想要浏览器打开一个本地页面就能调到上传核心（目标）；现在只有命令行，管理靠记命令（现状）；不做则管理台后续 issue 没有底座（代价）
- 行为：`panup serve` 起本地服务（127.0.0.1:8256 可配）；`GET /` 返回页面壳；`GET /api/status` 返回三灯体检；接口错误统一 `{code, msg, hint}` 信封；Ctrl+C 干净退出
- 机制：FastAPI + uvicorn（requirements.txt 锁版本）；SPA 静态资源由 FastAPI 托管；`web/api.py` 只调 core 公开函数（AC-01）

## 过程记录

- **check_all 的落点**：BACKEND §2 已把 `check_all` 声明为 core 公开函数，但代码里还没有；现状是 web 层如果自己拼体检逻辑就违反 AC-01。答案：按文档在 `core/pipeline.py` 补实现（注册表可注入供测试打桩，缺省用全局注册表），web 层只透传结果。
- **httpx 引入**：验收标准 A1 指名用 TestClient，而 starlette TestClient 需要 httpx（传递依赖）。现状是运行时最小集合只有 fastapi + uvicorn（AGENTS §11 条款 2）。答案：装为测试依赖并在 requirements.txt 注明「非运行时」，运行时依赖集合不变。
- **只监听回环的实现取舍**：host 原本可以做成 `[web]` 配置项；现状是配置一旦填 `0.0.0.0` 就破坏「只监听 127.0.0.1」红线。答案：host 硬编码回环、配置只放端口，并有测试断言「配置试图改 host 也改不动」。
- **验收前合并 main**（2026-11-09）：回程护栏提示分支落后 main（B1 收尾 + I-012 文档提交）。`cli.py` 冲突两边都保留——I-005/I-006 的 `cmd_watch` + `watch` 子命令与本次的 `cmd_serve` + `serve` 并存，顺序 watch → serve。
- **合并后一例测试失效**：`test_output_sorted_by_name` 只传 driver 注册表、writer 用全局表（建分支时全局为空），main 合入 I-005 后多出 `feishu` 一项致断言失败。答案：显式传 `writer_registry={}`，只验证排序本身；产品代码未改，全套 89 例绿。
- **环境提醒（验收 A4 会踩）**：本机 `pip` 指向 anaconda、`python` 是另一套 3.13，装依赖必须 `python -m pip install -r requirements.txt`，否则起服务报 `No module named 'fastapi'`。

## 自验

- A1［先写］：tests/test_web_api.py 新增 14 例（路由 / 信封 / 三灯透传 / 静态资源 / 回环），全套 73 例绿；变异检查：把 `resolve_bind` 的回环锁改坏 → `test_resolve_bind_locks_loopback` 变红 → 还原恢复绿。
