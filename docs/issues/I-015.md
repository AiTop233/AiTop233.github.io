## 目标

- 意图：一个文件要同时传百度 + 夸克（目标）；现在 `publish_file` 只认一个盘，传两盘要敲两遍命令、文档里散成两节（现状）；不做则盘越多越乱，文档一节一个盘的碎片无法合成一条资源（代价）
- 行为：一次任务传多盘，各盘独立成败、某盘失败不阻断其他盘；**全部跑完后只写一节**文档，节内只列成功的盘；标题由人指定，未指定用文件名；台账每个「文件 × 网盘」一行、同任务共享 `group_id`
- 机制：新增 `publish_task(local_path, targets, title=…)`，`publish_file` 转为单 target 特例；Writer 契约 `append_task(task)`；`uploads` 表加 `group_id` / `title`，启动时 ALTER 补列并回填 `legacy-<id>`

## 过程记录

- 结构：`publish_file` 的原有逻辑下沉为 `_publish_one`（单盘最小事务单元），`publish_task` 在其上做多盘循环 + 聚合 + 只写一次文档；`publish_file` 保留原签名，语义变为「只有一个 target 的任务」，watcher 与既有调用方零改动。
- Writer 契约：`append_task(task)` 取代 `append_record(record)`；`append_record` 降级为基类里的兼容包装（单盘 record → 单 item task），既有 81 例测试不用改就继续通过。
- 台账：`record_start` 增 `group_id` / `title` 参数；复用行（同键重传）时一并刷新归属，避免旧任务的标题残留在新任务里。

## 自验
