## 目标

- 意图：站点 540 条资源、7 个分类，但搜索引擎只认得出首页。不做则「内容再多也不进搜索结果」，等于没发布（代价）
- 行为：修掉阻断收录的硬错误，补齐每页的标题 / 描述 / 分享卡片 / 结构化数据，把 sitemap 与 robots 变成构建产物而不是手写清单
- 机制：全部集中在 `config.ts` 的 `transformHead` 与 `buildEnd`，一处改、全站生效；再用 `tools/seo-check.mjs` 把规则固化成对**产物**的断言

## 最严重的一条

```html
<!-- 改之前：每一个页面都是这一行 -->
<link rel="canonical" href="https://aitop233.github.io">
```

canonical 写在 `head[]` 里，VitePress 把它原样注入所有页面。等于明确告诉搜索引擎「/geektime/、/movies/ 都是首页的副本」——这类页面不会被单独收录，站内链接再多也没用。而且它不报错、页面能正常打开，只有把产物读出来才看得见。

## 边界

- **不做单资源页**（540 个 `/res/<slug>/`）：每条只有「一个链接 + 提取码」的页面属于薄内容，Google 侧有整站质量风险，收益不确定。理由与替代方案见 D-012
- **不换域名**：`github.io` 对百度的抓取本身就不稳，但换域名涉及备案与 301，不在本单；先把能控的部分做对
- **不做图片搜索**：站点目前没有配图，加图是内容工作，不是技术工作
- **不做自动内链**：资源之间没有标签体系，硬做只会生成一堆无关链接
