## 目标

- 意图：想把文件程序化地传进夸克网盘指定目录并拿到分享链接（目标）；现在夸克只能手动上传分享（现状）；不做则 F1 / F2 对夸克不可用（代价）
- 行为：登录态可校验；上传成功（含大文件分片）；分享返回链接与提取码；cookie 失效时报错并给出恢复指引
- 机制：参考 alist 夸克驱动的接口流程自建 `drivers/quark.py`（登录态 cookie、预上传 → 分片 → 落盘 → 分享接口），风格与契约对齐 `drivers/baidu.py`

## 过程记录

- 背景（规划期）：夸克无官方开放平台，社区方案均为网页接口 + cookie。风险已知：接口可能随官方改版失效、cookie 会过期、有风控可能——按 AC-06 失败必须显式报错，不静默。
- 目标：端点来源可查证。现状：夸克分享没有官方文档。答案：上传 / 列目录 / 建目录取自 alist `drivers/quark_uc` 源码（pre → hash → auth + OSS 分片 → commit → finish）；创建分享取自社区方案（POST /share → /task 轮询 → /share/password 取 share_url 与提取码）。主机统一用 drive-pc.quark.cn（alist 用 drive.quark.cn，两者都是网页接口主机）——真实验收时若主机不通，换 alist 的主机再试。
- 目标：会话不过期。现状：夸克响应会下发 __puus / __pus 会话 cookie（alist 为此专门做定时刷新，#830）。答案：驱动把响应中的 __puus / __pus 合并进内存 cookie（alist 同款做法）；落盘回写 secrets/ 不在驱动职责内，长跑场景的持久化留给后续 issue。
- 目标：夸克不支持同名覆盖（alist 标记 NoOverwriteUpload）。答案：upload 的 overwrite=False 直接报错并提示；overwrite=True 时同名行为交由服务端，真实验收时确认。
- 目标：错误码判定不过度。现状：社区对夸克错误码没有权威表。答案：status=401 或 code=31001 判登录态失效（AuthError）；其余按调用语义抛 UploadError / ShareError；31002（同名冲突）是业务错误，不误判为登录问题。真实验收时按实际返回补充 errno 表。
- 目标：文件颗粒度。现状：quark.py 521 行，超过 ~500 行软哨兵。答案：审视后判定单职责（同一上游 API 的契约方法 + OSS 直传），不拆；将来若加大文件直链、转存等功能再按职责拆。
