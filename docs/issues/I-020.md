## 目标

- 意图：让「别人的资源」能进来。现在系统的入口只有本地路径，`publish_task` 的入参就是 `local_path`；要转存只能人工下载再上传，一个 4 GB 的资源等于白折腾两遍（现状）；不做则「对接很多站点」永远只能靠手工（代价）
- 行为：粘贴一条分享链接 + 提取码 → 变成候选 → 转存进我的盘 → 按标题改名 → 分享 → 落台账 / 飞书，**全程不下载文件**
- 机制：新增 `sources/`（`Source` 基类 + 注册表 + `link` 源）与 `transforms/`（`Transform` 基类 + 注册表，本单只放一个恒等实现）；驱动加 `capabilities` / `supports()` / `resolve_share()` / `save_share()` / `rename()`；core 新增 `run_line()` 串起「发现 → 获取 → 加工 → 投放」，`acquire` 按能力选路径

## 边界

- 只做**同盘**转存（源盘 == 目标盘）。跨盘 `relay` **不实现**，命中即报错并指出「需下载再上传，属重成本路径」——先不给自己挖一个 3 倍耗时的坑
- 先只接一个盘的 `save_share`（夸克或 UC，开工前定）；其它盘按 `capabilities` 缺省为「不支持」，行为可预期
- 不改 `publish_task` 的签名；`run_line` 是它外面的一层编排
- 不做批量自动挑选（I-021）、不做名字模板（I-022）、不做媒体加工（I-023）

## 风险与对策

- **风控**：转存与分享都敏感。全程串行 + 步骤间隔 ≥ 1 秒；单轮上限；连续失败 3 次停线（AC-11）
- **协议不稳定**：夸克 `sharepage` 四步链是网页私有接口，会改版。错误必须显式（AC-06），且把「哪一步失败」写进错误码，便于定位
- **改名冲突**：服务端改名遇到同名会失败。策略 = 先查目标目录，重名则加 ` (2)` 后缀而不是覆盖

## 过程记录

- 调研结论见 `SOURCES.md` §3～§4：搜索站只是索引，真正「对接」靠解析 + 转存；夸克/UC 同构（`token → detail → save → task`），百度只能当目的地
- 关键取舍：`Candidate` 不带文件内容，所以「搜 50 条只挑 3 条」很便宜；这是让 I-021 的候选池可行的前提
