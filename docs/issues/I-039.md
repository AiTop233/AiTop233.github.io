# I-039 · 远端删除：驱动 delete + 两个接口 + 记录页按钮

- 状态：**待验收**（2026-11-09 实现；两盘验收目录已全部实机删干净）
- 批次：B3 收尾 / 代验遗留清理
- 来源：验收收尾时人要求「增加删除接口，并把每一次的结果删除」——此前验收目录只能手工到网页端删（DEVLOG I-017 / I-018 遗留项）

## 背景

驱动契约只有 `mkdir / upload / share / list`，没有任何删除能力，于是每轮验收在
百度、夸克留下的 `/panup验收-*` 目录越攒越多，只能人工登网页删。台账里的成功记录
也一直保留着已经失效的链接。

## 做什么

1. **驱动契约**：`Driver.delete(remote_paths, *, to_trash=True) -> {deleted, missing, failed}`
   - **与 I-027 的批量删除共用同一签名**（I-027 分支已按此实现）：`deleted` 是删掉的路径、`missing` 是远端本来就没有的、`failed` 是逐条归因 `{path, code, msg}`；单条失败不中断整批
   - 基类给默认实现，直接报 `PUP-422`「驱动不支持删除」——老驱动与测试桩不必跟着改（AC-02 只增不改）
   - 百度：`POST /api/filemanager?opera=delete&onnest=fail&channel=chunlei`（`async=1` 自适应），`filelist=[path...]`，按 `info[].errno` 逐条归因，-9/31066 归 `missing`
   - 夸克：`_fid_of` 解析 fid → `POST /file/delete`（`action_type=1` 即回收站）；整批被拒时退化为逐条重试；成功后清掉该路径及其子路径的 fid 缓存
   - 幂等：远端本来就没有 → 进 `missing`，不算失败（删验收目录常常「上一轮删过一半」）
   - 根目录：进 `failed`（`PAN-<盘>-root`），且在发请求之前就拒（不打网盘）
   - `to_trash=False`（彻底删）两个盘都直接拒：网页接口只做回收站，彻底删要人到网页端清空
2. **台账状态**：新增 `deleted`；`record_deleted(id)`（单条）与 `mark_deleted_by_remote(pan, path)`（前缀批量）；`link`/`pwd` 清空，行保留可追溯；`tasks()` 聚合出 `deleted`
3. **接口**：
   - `POST /api/uploads/{id}/delete-remote` → 删这条记录的 `remote_path`；已删过返回 `skipped`；远端不存在仍标 `deleted`
   - `POST /api/remote/delete`（`{pan, path}`）→ 按显式路径删（台账里查不到的路径也行），顺带把该前缀下的成功记录标 `deleted`（返回 `records`）
   - 两道闸：`pan` 未注册 → `PUP-405`；`path` 是根 → `PUP-108`（都在打网盘之前）
   - 接口层只传一条路径给驱动的批量契约，`missing` 按成功处理，`failed` 折算成项目错误
4. **页面**：记录页每个成功项多一个「删远端」小按钮，`confirm` 二次确认，删完行变「远端已删除」+ 徽标「已删除」

## 已知边界

- **百度风控**：`errno 132` 是账号级安全校验，偶发（同一批里有的成功有的被拒），
  等几秒重试即可通过；接口已把它映射成可直接照做的中文提示，批量删时建议带 3 次重试。
- **与 I-027 的关系**：I-027（文件页：批量改名 / 批量删除）在自己的分支里已经实现了
  同名同签名的 `Driver.delete`；本单是**同一契约的另一半**（记录页入口 + 台账状态），
  合并 I-027 时驱动层取它的实现，接口层不冲突。
- 删除是**服务端递归**：给目录就删整棵子树，没有「只删空目录」这一档。
- 删除会连带让已分享的链接失效（分享的是同一个 fid），页面确认框已写明「不能撤销」。
- 只删远端，不删台账行、不删 `data/inbox` 本地副本——本地副本清理由收尾脚本负责。
