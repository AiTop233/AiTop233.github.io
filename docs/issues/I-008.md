## 目标

- 意图：想拖个文件进浏览器就完成上传拿链接、历史记录随时可查（目标）；现在只能敲命令、记录要看终端（现状）；不做则「难管理」的核心痛点不解决（代价）
- 行为：上传页拖拽/选文件 → **网盘多选（可只勾一个）且每个勾选的盘单独设目录** + 标题（可留空用文件名）+ 日期开关（+可选写入飞书）→ 显示各盘链接与提取码（可复制）；记录页按任务列出（时间 / 标题 / 各盘链接 / 状态），失败项集中进「待修」并可单条重试；错误顶部提示条带「怎么办」
- 机制：`POST /api/upload`（multipart 流式转发；`pans` 为 `{pan, dir}` 数组、`title` 可选）、`GET /api/uploads?status=`、`POST /api/uploads/{id}/retry`；前端 state 整体刷新

## 过程记录

**目标**：浏览器里拖一个文件、勾若干网盘、拿到每条链接，历史与失败项都在页面上管。

**现状（开工前）**：I-007 只有页面壳与三灯，四个面板是空态文案；核心已有 `publish_task`（D-004 多盘任务层）与台账 `group_id`。

**试错与答案**

1. **浏览器上传的文件怎么让台账记住**
   - 试：直接把 `UploadFile` 的临时文件交给管道。风险是上传完临时文件即删，台账 `local_path` 指向已消失的路径，失败项重传必然 409。
   - 答案：先落到 `data/inbox/<时间戳-随机>/<原文件名>` 再交给管道。代价是占磁盘（暂不清理，后续可加保留期）。测试 `test_upload_keeps_original_filename_in_persistent_inbox` 锁住「落在 inbox、保留原名」。

2. **重传要不要写飞书**
   - 试：重传时传 `writer_names=["feishu"]` → 文档会多出一节同名小节（标题相同、只有一行），一个资源两节，比缺行更难看。
   - 答案：重传**不写文档**，页面提示「飞书文档未追加（避免同一资源出现两节）」。若以后要求「补上缺的那行」，需要 writer 支持向已有小节追加行，另开 issue。

3. **骨架图又是先写代码后出图**
   - 事实：I-008 骨架表要求「开工时出图、人确认后出视觉」，我这次仍是先写完后补图（`-default.png` / `-empty.png` 在代码跑通后才生成）。I-007 记过同一条教训，没吃透。
   - 处理：图已补并在骨架表标注「待确认」；若结构要改，按图改代码，不按代码改图。

4. **A4 第一次验证的等待条件写错**
   - 现象：等「待修数 = 0」，但台账里还有 3 条历史失败，重传成功后是 4→3，脚本超时。
   - 答案：改为盯目标行（按文件名定位）+ 断言待修数正好减 1，复验通过。不是产品缺陷。

5. **历史失败记录的 `PUP-000`**
   - 现象：早期记录只有错误码没有原因，页面直接显示 `PUP-000`，看不懂。
   - 答案：前端错误码映射，`PUP-000` → 「未分类失败（旧记录）」，常见码（noauth / nodir / net / share / quota）也给了人话；未知码原样显示，鼠标悬停可看原始码。

6. **日期开关默认状态与默认目录（人 2026-11-09 追加要求）**
   - 事实：网页「按日期建子目录」原本默认不勾，而 watch 的 `date_dir` 缺省为 `true`，同为入口却默认相反。
   - 答案：网页改为**默认勾上**，与 watch 一致；人给的默认目录是 `/流量生意/十八线资源/26`、`/003-十八线资源/26`（末尾已是年份），而 `date_subdir()` 无条件拼 `年/月/日`，直接写会得到 `26/26/11/09`。故 `[pan]` 里写**年的父级** `/流量生意/十八线资源`、`/003-十八线资源`，由日期层生成 `26/11/09`。
   - 印证：只读扫描现网已有结构为 `26/11/08/piliplus/`（内含 ipa / dmg / zip / apk 四个文件），与 D-005「年/月/日/资源名/文件」完全一致，百度与夸克两边为同一份镜像。

**新增依赖**：`python-multipart==0.0.33`（FastAPI 解析 multipart 表单必需），已锁进 `requirements.txt`。

7. **验收时发现：待修列表把错误码当成人话**（2026-11-09，人指着截图指出）
   - 现象：待修里出现 `PAN-name-conflict`（两条）、`PAN-quark-31001` 两行原始码，只有 `PUP-000` 显示成「未分类失败（旧记录）」。
   - 原因：台账只存 `error_code`，`msg` / `hint` 没落库；前端 `errText` 只按几个关键字匹配，没覆盖到的码原样返回（第 5 条当初就写了「未知码原样显示」，这次人明确不接受）。
   - 处理：前端改成「原因 + 怎么办」两行——`errInfo()` 用映射表 + 模式匹配，覆盖 `name-conflict`（同名资源已存在）、`31001`（登录态失效）、`31002`（同名文件）、`-9`（目录不存在）、net / html / token / share / part / oss / pre / nofile / quota；原始码只留在 `title` 里备查。记录页的失败行同样处理。
   - 未做：把 `msg` / `hint` 落进台账（要改表结构，属第 3 档；且历史失败行原文已丢，本轮只在展示层还原）。

8. **A5 在链顶批量入口退化**（2026-11-09 验收期发现）
   - 现象：I-008 的单文件入口本来就说清了「夸克失败：<原因>（怎么办: <hint>）」，但链顶的批量入口（I-018 的 `finishUpload`）把它换成了「1 个网盘没传成功，见结果里的红字」——只报个数，不说原因，恰好退回到 A5 要防的那种「看得见失败、看不懂为什么」。
   - 处理：在 I-018 分支把 `result.failed` 映射回「盘名 + 原因 + 怎么办」，与单文件入口同一句法（`a6113a8`）。I-018 验收时一并看。
