## 目标

- 意图：想上传完成后的链接自动出现在我的飞书文档里（目标）；现在要手动复制粘贴链接，记录散在各处找不回（现状）；不做则分享记录无法沉淀，回查要翻聊天记录（代价）
- 行为：配置指定目标飞书文档；每次成功上传后向该文档追加一行「时间 · 文件名 · 链接（提取码）」，链接可点击；凭证失效或文档无权限时报错含恢复指引，且不阻塞上传本身
- 机制：`writers/feishu.py` 直调飞书开放平台 docx API（tenant_access_token 获取并缓存、向文档追加文本块、text_run 设置 link 样式）；注册进 core 的 writer 注册表，I-004 的 `--doc feishu` 接线生效

## 过程记录

- 背景（规划期）：飞书自建应用需在开放平台创建并开通云文档权限，目标文档需授权给应用（一次性人肉操作）；腾讯文档写入列 PRD「后续阶段」，本 issue 只做飞书。
- 目标：追加位置语义。现状：docx API 追加块需要 block_id。答案：直接向页面块（block_id = document_id）追加 children，不传 index 即落在末尾，省一次「列全部块」调用。
- 目标：链接可点击。现状：text_run 的 link.url 要求百分号编码。答案：`quote(link, safe="")` 全量编码（变异检查验证过此处）。
- 目标：错误分类不过度。现状：社区对飞书错误码没有权威表。答案：token 类 99991661/63/68 与 99991672（无权限）映射 AuthError（带「文档授权给应用」指引）；其余按 WriterError——真实验收时按实际返回补 errno 表。
- 目标：writer 失败不翻转上传状态（PRD F3）。现状：管道对 writer 逐个捕获，结果进返回值 `writers` 列表（I-004 已实现挂载点）。
- 目标：文件颗粒度。现状：feishu.py 205 行。答案：低于哨兵，单职责不拆。
- 目标：写入权限（验收期）。现状：应用对文档可读不可写（1770032）——读通 + 写禁证明版本已发布、只读范围已生效，缺的是文档侧授权。答案：人在文档里把应用权限改成「可编辑」后写通；无权限报错的指引与真实修复路径吻合（A4）。
- 目标：追加写法符合人的文档版式。现状：人验收时指出追加行与其版式不符（其版式为「YYMMDD 主题」h2 标题插最顶 +「盘名：链接」行、pwd 内嵌 URL）。答案：已按 I-012 记想法（涉 PRD F3，转待办先过规划模式），本 issue 按冻结标准验收通过。
