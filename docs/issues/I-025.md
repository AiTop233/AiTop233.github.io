## 目标

- 意图：本机另有一个用 VitePress + GitHub Pages 搭的资源站，540 条资源链接，但和上传工具各在各的目录、各写各的格式；不做则「上传完还要手工去站上贴一条」，两边内容只会越来越对不上（代价）
- 行为：站点源码搬进本仓库 `site/`，一处 clone 就有「上传 + 内容站」；站点内容只有一个写入点，后续同步不必改页面代码
- 机制：`git subtree add --prefix=site` 保留原仓库提交历史；分类页从内联 `const resources = [...]` 改为 `import data from '../data/resources.json'`；新增 `tools/extract.mjs`（一次性抽取）与 `tools/add.mjs`（唯一写入点）

## 边界

- **不动线上仓库**：部署源仍是 `AiTop233.github.io`，本仓库只做编辑副本；发布用 `git subtree push --prefix=site site-pages main`，由人决定何时推
- **不改视觉**：卡片组件、配色、导航、SEO 头一律不动；只把数据从 markdown 里搬出去
- **不做同步**：本单只准备写入点，`panup → site` 的映射规则与触发方式属 I-026
- **不接 Vercel**：原项目实际是 GitHub Pages + Actions（`aitop233.vercel.app` 返回 404）；若以后要回 Vercel，Root Directory 填 `site` 即可，本单不预先加配置

## 风险与对策

- **两处内容不一致**：站点仍在旧仓库发布，若有人直接在旧仓库改内容，`subtree push` 会冲突。对策：旧仓库只读，改内容一律在本仓库 `site/` 下改（README 写明）
- **分类页是手写 Vue**：`{{ count(...) }}` 依赖 `data.counts`，若 JSON 被手改成缺 `counts`，首页数字会变 0。对策：`tools/add.mjs` 每次写入都重算 `counts`
- **构建环境差异**：本机沙箱的删除拦截会让 `vite` 清空 `dist` 时报 `ETIMEDOUT`，与项目无关，已写进 README 的规避步骤
