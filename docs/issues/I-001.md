## 目标

- 意图：想要一个配置与密钥有固定去处、错误与日志格式统一的项目底座（目标）；现在目录里没有任何代码（现状）；不做则后续每个模块各自造配置读取与报错格式，凭据散落有泄露风险（代价）
- 行为：配置从文件与环境变量加载，缺必需项时一次性报出全部缺失清单；日志按 JSON lines 落盘；错误类型统一携带错误码与恢复指引
- 机制：`config.py` 用 `tomllib` 读配置、环境变量覆盖；`core/errors.py` 定义 `ProjectError` 族；`core/log.py` 写 JSON lines

## 过程记录

- 目标：config 的报错要统一走 ProjectError 契约。现状：ARCHITECTURE 模块表 config 行「允许依赖 —」，而统一错误类型在 core/errors.py，config 引它似与依赖方向相悖。试错：config 自定义异常或返回元组——前者破坏统一错误契约，后者把报错语义推给每个调用方。答案：把 core/errors.py 明确为零依赖叶子模块（docstring 已注明），config 仅 import 错误类型，不触碰 core 其他成员，不构成业务反向依赖。
- [补空白] ARCHITECTURE 模块表 config 行需补注「允许依赖 core.errors（仅错误类型，零依赖叶子）」——待规划模式同步后在 DEVLOG 追加 [已同步]。
