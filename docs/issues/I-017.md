## 目标

- 意图：一个资源传上去应该是网盘上**一个文件夹**、一条链接覆盖它全部内容（目标）；现在只能传单文件、链接指向文件，传文件夹直接不支持（现状）；不做则资源包只能拆开传、一个资源散成多条链接，网盘上也没有「资源」这个概念（代价）
- 行为：`publish_task` 接受**文件或文件夹**；每个盘落 `remote_dir/[年/月/日/]标题/` 的资源文件夹，内部按本地相对路径镜像（子目录原样保留、空目录跳过）；**单文件也建这一层**；网盘上已有同名文件夹 → 报错并提示换标题，不合并；分享链接指向该文件夹；台账每「资源 × 网盘」一行，记 `kind`（file/folder）与 `file_count`；重传跳过网盘上已存在且大小一致的文件
- 机制：`_publish_one` 由「单文件」改为「资源」；新增资源扫描（相对路径 + 大小）、标题清洗（非法字符替换）、同名检查（`list` 父目录）、逐文件 `mkdir` + `upload`、`share(资源文件夹)`；`publish_file` 保持签名转单 target；CLI `upload` 的路径参数支持目录；`uploads` 加 `kind` / `file_count` 列并迁移存量

## 过程记录

**目标**：一次上传 = 网盘上一个以标题命名的文件夹，单文件也一样；链接指向文件夹。

**现状（开工前）**：`_publish_one` 是「单文件 → 目录」，远端路径 = `目录/文件名`，分享指向文件；前端拖文件夹无反应，CLI 传目录直接报「本地文件不存在」。

**试错与答案**

1. **夸克分享文件夹拿不到 share_id**
   - 现象：真实上传时百度成功，夸克报「创建分享未返回 share_id」，但文件其实已经传上去了。
   - 排查：打桩打印原始响应，`POST /share` 只回 `{task_id, task_sync: false}`；轮询 `/task` 到 `status=2` 时，`share_id` 在 **`data.share_id` 顶层**，而代码只读了 `data.task_resp.data.share_id`。单文件走同步分支（`task_sync=true`）所以一直没暴露。
   - 答案：`_wait_task` 两种形状都认（先 `task_resp.data.share_id`，再顶层 `share_id`），并加用例 `test_share_task_reads_top_level_share_id` 锁住。

2. **同名冲突该不该进「待修」**
   - 试：冲突先写 `failed` 台账 → 记录页出现一条待修；点重传走 `force` 会绕过冲突检查，把这个资源**合并**进别人的同名文件夹。
   - 答案：冲突是用户写错标题，属预检查，放在 `record_start` **之前**抛出，不写台账；`force` 才保留「补传已有资源」的语义。用例断言冲突后台账为空。

3. **单文件也建标题层，旧断言全线失效**
   - 现象：`test_pipeline` / `test_cli` / `test_watcher` 里「分享路径 = `/分享/a.txt`」的断言全红。
   - 答案：按 D-005 统一改成 `/分享/a`（分享指向标题文件夹），并新增 `tests/test_resource.py` 12 例覆盖新语义；不是放宽断言，是验收标准本身变了。

4. **空目录与标题清洗**
   - 空子目录不产生条目，自然跳过；整个文件夹没有文件时抛 `PUP-105`（否则会在网盘上建一堆空壳）。
   - 标题会直接当远端文件夹名，故 `/ \ : * ? " < > |` 与控制字符一律替换为 `_`，顺带堵住 `../` 越级；清洗后为空退回文件名或「未命名」。

**新增依赖**：无。
