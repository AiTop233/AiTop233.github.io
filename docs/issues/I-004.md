## 目标

- 意图：想一条命令完成「上传 + 拿链接」（目标）；现在驱动有了但要手工串步骤、没有去重与记录（现状）；不做则每次上传都要多步操作且容易重复传（代价）
- 行为：一条命令上传到指定网盘指定目录，输出链接与提取码；同一文件重复上传时提示去重并返回已有链接，`--force` 可强制重传；失败时退出码非 0 并输出恢复指引；`status` 子命令可查最近上传记录
- 机制：`core/pipeline.py` 编排去重检查 → mkdir → upload → share → writer → 台账；`core/ledger.py` SQLite 台账；`cli.py` 用 `argparse` 暴露 upload / status 子命令

## 过程记录

- 目标：writer 失败不能把已成功的上传翻转成失败（PRD F3）。现状：初版 writer 异常会被管道的 except ProjectError 捕获并 record_failed。答案：writer 名先在管道入口校验（未注册=配置错误，fail fast）；已注册 writer 的运行期失败逐个捕获进返回值 `writers` 列表，台账保持 success。
- 目标：台账连接生命周期。现状：Windows 下 SQLite 连接未关闭，临时目录清理报 WinError 32。答案：Ledger 增加 close()，CLI 每条命令用完即关。
- 目标：Git Bash 可用性。现状：`--dir /panup验收` 被 MSYS 路径转换改写成 Git 安装路径——百度驱动的 _norm 防御（I-002 移植）正确拦截并给出指引；本地样例文件路径同样被 `/tmp` 坑。答案：Git Bash 下命令加 `MSYS_NO_PATHCONV=1` 前缀、本地路径用 cygpath 转 Windows 形式；该用法已写进「怎么验收」，AGENTS 常用命令的补注待规划修订时确认。
- 补空白（第 2 档）：为管道挂载点新增 `writers/`（Writer 基类 + 注册表，本 issue 只建注册点，飞书实现在 I-005）——ARCHITECTURE 模块表已有 writers 行，无需改图；writer 失败不阻塞上传的语义来自 PRD F3，已在 docstring 注明。
